# ТЗ: нативный IPTV-плеер для Android TV

Полноэкранный IPTV-плеер для Android TV с ТВ-гидом, архивом и напоминаниями. Эталон поведения — это ТЗ, `docs/controls.md` (раскладка и окна) и `docs/design.md` (оформление). Если они о чём-то молчат — решение записывается в них.

## 1. Цели и границы

**Цели**
- Полноэкранный IPTV-плеер для пульта: эфир, архив (catchup), EPG, ТВ-гид, напоминания, избранное. Раскладка клавиш — `docs/controls.md`.
- Плейлист и программа загружаются **потоково** и сразу пишутся в БД. Каналы и передачи появляются в интерфейсе по ходу загрузки. Файл целиком в память не читается.
- EPG по умолчанию берётся из плейлиста (`url-tvg` / `x-tvg-url`). Пользователь может добавить свои источники или заменить источники плейлиста своими.
- Приложение должно работать на слабых приставках (Amlogic S905, 1–2 ГБ ОЗУ, Android 6–9).

**Не входит в первую версию**
- Сервис epg.rootu.top. Его справочник каналов, JSON-API программы и CORS-прокси не нужны: XMLTV разбираем сами.
- Поиск по внешним каталогам фильмов.
- Отдельный телефонный и планшетный интерфейс (тач и мышь поддерживаются в ТВ-интерфейсе, см. §10).
- Запись эфира, Chromecast, профили.

## 3. Данные и БД

Все времена хранятся в unix-секундах (UTC). Схема версионируется (`onUpgrade`).

```
playlist        id, name, url, epg_mode(0 — из плейлиста, 1 — плейлист + свои, 2 — только свои),
                user_epg (список URL через \n), header_epg (из #EXTM3U), loaded_at, etag, last_modified,
                channels_count, error, sort
channel         id, playlist_id, num, key, name, url, grp, logo, tvg_id, tvg_name, tvg_shift,
                catchup_type, catchup_source, catchup_days, user_agent, referrer, headers_json,
                epg_source_id, epg_xml_id   — сопоставление с EPG (заполняет матчер)
                UNIQUE(playlist_id, num)
epg_source      id, url, loaded_at, etag, last_modified, status, error, programmes_count
epg_channel     source_id, xml_id, names (через \n), icon        PK(source_id, xml_id)
programme       source_id, xml_id, start, stop, title, sub_title, descr, category, icon, load_id
                PK(source_id, xml_id, start)  WITHOUT ROWID
                индекс (source_id, xml_id, stop)
favorite        playlist_id, key, sort
history         playlist_id, key, at
hidden          playlist_id, kind(group|channel), key, title
score           playlist_id, key, value                     — адаптивная сортировка
reminder        id(key:start), playlist_id, ch_key, ch_name, ch_num, logo, start, stop, title, descr, snooze
epg_map         source_id, ch_key, xml_id                    — сопоставление канала с EPG (по ключу канала)
```

- Настройки и «где остановились» (последний плейлист, канал, категория) — `SharedPreferences` (`core/Prefs`).
- **Ключ канала** `key` — нормализованное имя (аналог `favId`). На нём держатся избранное, история, скрытое и напоминания, поэтому они переживают перезагрузку плейлиста, если номера каналов поменялись.
- Источник EPG общий для плейлистов: если один URL указан в нескольких плейлистах, он скачивается один раз.
- Перезагрузка плейлиста — замена каналов в одной транзакции. Пользовательские таблицы ссылаются на `key`, поэтому не теряются.
- Программа хранится только для каналов плейлистов (сопоставленных, `epg_map`) в окне `[сейчас − (глубина архива канала + 1 сутки); сейчас + 8 суток]`: глубина — своя у канала (нет архива — 0, нет своей — общая из настроек), у xml-канала, общего для нескольких каналов, — наибольшая. Остальное отбрасывается при разборе (до разбора содержимого: `XmltvParser.accept`), старше окна — удаляется при каждой загрузке.
- **Прошлое не перезаписывается.** Всё, что закончилось раньше начала сегодняшнего дня (местное время), и попадает в уже сохранённый у канала диапазон (первая…последняя передача прошлого в БД), не разбирается и не пишется: вчерашняя программа не меняется. Прошлое вне этого диапазона (выгрузка стала глубже) дописывается.

## 4. Потоковый парсер плейлиста (M3U/M3U8)

Источник — HTTP(S) URL или локальный файл (`content://` через выбор файла, фаза 5).

- Поток: OkHttp body → определение сжатия по первым байтам (`1F 8B` — gzip, `PK` — zip, берётся первый `.m3u*`) → `BufferedReader(UTF-8)` → разбор построчно. Сначала снимается BOM, затем учитываются `\r\n`.
- Каналы пишутся в БД пачками (по 500 в транзакции) и после каждой пачки приходит событие прогресса. Сначала каналы пишутся во временный набор, а по успешному окончанию заменяют старые одной транзакцией. Пока идёт перезагрузка, интерфейс показывает старый список. При первой загрузке список показывается по мере разбора.
- Правила разбора:
  - `#EXTM3U` — атрибуты заголовка: `url-tvg`, `x-tvg-url`, `catchup`, `catchup-type`, `catchup-days`, `catchup-source`, `tvg-rec`, `timeshift`, `tvg-shift`. В `url-tvg` бывает **несколько URL** через запятую или пробел, их надо разделить.
  - `#EXTINF:-1 attrs,Название`: название начинается после **первой запятой вне кавычек**. В значениях атрибутов бывают запятые, например `http-user-agent="… (KHTML, like Gecko) …"`. Атрибуты: `key="v"`, `key='v'`, `key=v`, ключи регистронезависимы.
  - `#EXTGRP:` — группа для следующих каналов, если нет `group-title`.
  - `#EXTVLCOPT:http-user-agent=…`, `#EXTVLCOPT:http-referrer=…`; атрибуты `http-user-agent` и `http-referrer`/`referer` в `#EXTINF`; `#EXTHTTP:{json}` — произвольные заголовки. Всё это сохраняется в канал и применяется при воспроизведении.
  - Строка URL (http, https, rtmp, rtsp, udp — дальше решает плеер) завершает канал. YouTube-ссылки пропускаются. Без `#EXTINF` канал получает имя `Ch N`.
  - Из имени убираются служебные значки `ⓢⓖⓥⓞ`, лишние пробелы схлопываются.
  - Архив канала: `catchup-days` / `tvg-rec` / `timeshift` у канала или в заголовке, `catchup-enable`, явный `catchup` / `catchup-type` / `catchup-source`. `catchup="disabled"` архив выключает. Если глубина не указана — берётся настройка «Глубина архива по умолчанию».
- Ошибки `no_url | network | http_<код> | format | empty` показываются на экране ошибки с кнопками «Повторить» и «Настройки».
- Тесты (JVM, JUnit): запятая в user-agent, EXTGRP, catchup-атрибуты, BOM, CRLF, gzip-поток, поток, который обрывается на середине.

## 5. Потоковый парсер EPG (XMLTV)

Свой разборщик на уровне байтов (`data/XmltvParser`). Общий XML-парсер (`XmlPullParser`) декодирует и токенизирует каждый символ и до цели по скорости не дотягивает. Здесь у `<programme>` читается только открывающий тег. Передача ненужного канала пропускается поиском `</programme>` по сырым байтам без декодирования, а канал сравнивается побайтно с каналом предыдущей передачи (XMLTV идёт по каналам подряд). Нужные элементы копируются и разбираются маленьким разборщиком (title, sub-title, desc, category, icon, `lang`, сущности, CDATA, вложенные теги). Замер на ПК — около 240 МБ/с на синтетике в худшем случае (каналы чередуются), тест `XmltvEdgeTest.throughput`.

- Поток: OkHttp body → `BufferedInputStream` → автоопределение: `1F 8B` → `GZIPInputStream`, `PK` → `ZipInputStream` (первый файл), `FD 37 7A 58 5A` (xz) → ошибка «формат не поддерживается» (фаза 5). Затем XML. Кодировку берём из пролога XML (обычно UTF-8, бывает windows-1251).
- `<channel id>`: `display-name` (все, с учётом `lang`), `icon src`. Пишется в `epg_channel`.
- `<programme channel start stop>`: `title`, `sub-title`, `desc`, `category`, `icon`. Если есть несколько языков, предпочитается язык интерфейса, затем `ru`, затем первый.
- Время XMLTV: `yyyyMMddHHmmss ±hhmm`. Смещение может отсутствовать (тогда UTC), секунд может не быть. Если `stop` нет, концом считается начало следующей передачи канала. Перекрытия обрезаются по началу следующей передачи.
- **Фильтр по каналам плейлиста.** XMLTV почти всегда начинается со всех `<channel>`. На первом `<programme>` матчер сопоставляет каналы плейлиста с `epg_channel` (см. §6) и строит множество нужных `xml_id`. Передачи остальных каналов пропускаются, не доходя до БД. Если `<channel>` попадётся уже после передач, множество пересчитывается.
- Запись: `INSERT OR REPLACE` пачками по ~2000 строк в транзакции, `load_id` текущей загрузки. Каждая транзакция сразу видна интерфейсу (WAL), поэтому программа «наливается» на глазах. После успешного окончания в одной транзакции удаляются: передачи каналов, которых нет в сопоставлении; **заменённые** — прошлой загрузки с `stop` позже начала сегодняшнего дня и `start` не раньше первой передачи новой выгрузки канала (нет новых передач на сегодня и дальше — все будущие канала); старше окна хранения. **Прошлое, которого в новой выгрузке нет, остаётся** — оно нужно для архива. `programmes_count` источника — всего передач в БД (в логе «записано N (в БД M)»). При ошибке посередине данные этой загрузки остаются, а старые не удаляются.
- Кэш HTTP: `If-None-Match` / `If-Modified-Since`, ответ `304` — не разбирать. Автообновление — раз в N часов (по умолчанию 12) и при запуске, если данным больше суток.
- Нагрузка: разбор идёт в отдельном потоке с пониженным приоритетом, интерфейс не блокируется. Цель — 1000 МБ распакованного XML на S905X меньше чем за 60 с, пик памяти — не больше 30 МБ сверх базового.
- Прогресс (байты из `Content-Length`, число передач) показывается в настройках источника и тихой строкой в гиде («Программа загружается… 45%»).
- Тесты: смещения времени, без `stop`, многоязычные поля, CDATA и сущности, gzip, фильтр каналов, обрезка перекрытий.

## 6. Сопоставление каналов с EPG

Для каждого канала плейлиста по источникам EPG плейлиста, в порядке приоритета:

1. `tvg-id` == `xml_id`;
2. `tvg-name` или имя канала == одно из `display-name`, после нормализации (`Names`): нижний регистр; без «(архив)», «телеканал», «канал», «тв», «orig», «50»; `(+2)` → `+2`; знаки → пробел; «канал 5» → «канал5». Затем сравнение с транслитерацией похожих букв (`а→a`, `о→o`, `з→3`, …);
3. логотип: `tvg-logo`, иначе `icon` из EPG.

Результат пишется в `channel.epg_source_id/epg_xml_id` после загрузки EPG или плейлиста. `tvg-shift` (часы) сдвигает программу канала при показе.

## 7. Время

- Логика использует `now()` — unix-секунды с поправкой. Поправка берётся из заголовка `Date` ответов сервера плейлиста или EPG, если расхождение больше 30 с (у дешёвых приставок часы уплывают). 
- Часовой пояс — системный. Форматы дат и дней: «Сегодня», «Вчера», «Завтра», иначе «Пн, 02.11»; вкладка даты — «пн,\n2 нояб.».

## 8. Воспроизведение

Один экземпляр ExoPlayer на всё время работы, `PlayerView` без своих контролов (`useController=false`), оверлей наш.

- Источник: `DefaultMediaSourceFactory` с `OkHttpDataSource.Factory`: User-Agent и Referer канала, заголовки из `#EXTHTTP`. Тип — по расширению или MIME (`.m3u8` → HLS, `.mpd` → DASH), иначе progressive с автоопределением (MPEG-TS).
- Буферизация: короткий старт (`bufferForPlaybackMs` ≈ 1000) для быстрого переключения каналов. При ошибке эфира — повтор через 2, 5, 10 с, потом экран «Канал недоступен» в оверлее.
- **Архив** — шаблоны (`CatchupUrl`, тип — атрибут `catchup`/`catchup-type`, без него: `catchup-source` начинается с `?`, `&` или `/` — append, иначе default; без источника и без `${` в адресе — shift): `shift`/`timeshift`, `append`, `default`, `flussonic*`/`fs`, `xc`, `${start} ${utc} ${end} ${utcend} ${offset} ${duration} ${now} ${lutc} ${timestamp}`, `${(b)yyyy-MM-dd:HH-mm}`, `${(e)…}`, `${(n)…}`, `(bu)`, `(b+3)`, `${(d)M|S|h|m}`. Тесты — `CatchupUrlTest`. Примеры: shift — `…/index.m3u8?utc=${start}&lutc=${timestamp}`; flussonic — `/index.m3u8` → `/archive-${start}-${duration}.m3u8`, `/mono.m3u8` → `/mono-…`, `/video.m3u8` → `/video-…`, `/mpegts` → `/timeshift_abs-${start}.ts`; xc — `/live/u/p/1477.m3u8` → `/timeshift/u/p/${(d)M}/${(b)yyyy-MM-dd:HH-mm}/1477.m3u8`. Шаблон без `${` после разбора — shift.
- Позиция и время в архиве:
  - HLS с `#EXT-X-PROGRAM-DATE-TIME` (Flussonic и др.): позиция — реальное время кадра из плейлиста (`windowStartTimeMs + currentPosition`), если оно правдоподобно (окно архива в пределах суток до «сейчас»); плеер начал не с начала ссылки — ставится на него;
  - иначе `archive.start` — реальный момент начала ссылки, `archive.base` — позиция плеера, соответствующая ему (начало окна у «эфирного» HLS, 0 у конечного видео), `position = start + (currentPosition − base)`; «растущий» плейлист без PROGRAM-DATE-TIME плеер начинает у края — ставится в начало окна;
  - **Flussonic HLS**: передача моложе 6 ч — `archive-START-now.m3u8`: EVENT-плейлист (от начала до «сейчас», дописывается), недавнюю передачу можно смотреть до края эфира без переподключений; старше — обычное окно VOD `archive-START-DURATION`. Плеер начинает EVENT у края эфира (так и в документации Flussonic) — по PROGRAM-DATE-TIME ставится на начало. `?event=true` из документации не используется: балансировщики провайдеров (проверено на balelbrus) отбрасывают параметры и отдают VOD с концом «сейчас». Архив в плеере играется без подгонки скорости к краю эфира (скорость 1.0);
  - перемотка внутри окна потока — `seekTo`, за его пределами — новая ссылка;
  - продолжение при `STATE_ENDED`, при остановке на 15 с или при фатальной ошибке (не чаще раза в 15 с);
  - позиция догнала эфир — переход в эфир;
  - ссылки никогда не переиспользуются.
- **Пауза эфира**: позиция запоминается. После продолжения, если сдвиг больше 3 с, включается режим «архив со сдвигом» (бейдж «Архив», «−0:45»). Пока поток держит окно (HLS DVR), идёт он, иначе — catchup-ссылка на позицию паузы.
- Перемотка: нажатие — 30 с, удержание — скорость растёт от времени удержания (от 30 с до 10 мин эфира в секунду), применение через 0,9 с.
- Качество (бейдж SD/HD/FHD/4K) — по высоте видео из `onVideoSizeChanged`.
- **Звук и субтитры**: дорожки потока (`Playback.tracks`), выбор — `TrackSelectionOverride`; язык выбранной дорожки сохраняется (`Prefs.audioLang` / `subtitleLang`) и задаётся плееру как предпочитаемый.
- **Телетекст** (DVB, EN 300 472 / EN 300 706; `teletext/Ttx.kt`, `player/TeletextTs.kt`): ExoPlayer дорожку телетекста не читает, поэтому HLS из MPEG-TS собирается со своей фабрикой читателей (`TeletextHlsExtractorFactory`): дорожка PMT с дескриптором 0x56 идёт в `TtxDecoder` (все страницы канала копятся, пока играет поток; сброс при смене канала) и, если пришла страница субтитров, — текстовой дорожкой плеера «Телетекст» (`application/x-media3-cues`, время — PTS пакета, показ до следующей страницы). Страница субтитров — первая из объявленных в дескрипторе как субтитры (кроме 100, её каналы указывают ошибочно), помеченная битом «субтитры» в заголовке или 888; заглушка «ПРОГРАММА ТРАНСЛИРУЕТСЯ БЕЗ СУБТИТРОВ» не показывается. Экран телетекста (`TeletextLayer`) — Canvas 40×25 в области 4:3: цвета, мозаика (смежная и раздельная), двойная высота, мигание, скрытый текст, Fastext. Набор знаков — по пакету X/28 или M/29 страницы (код 0x24 — русский/болгарский), без него кириллица, если язык дорожки rus/ukr/bul…, иначе латиница с национальным вариантом из заголовка; расширения уровня 1.5 (пакеты X/26): знак G0, знак G2 и G0 с диакритикой (в частности «ё» = «е» + диерезис) — поверх знаков страницы; цвета, мозаика G3, объекты и DRCS из X/26 пропускаются. Двойная ширина (коды 0x0E, 0x0F) — знак на две ячейки, знак правой не показывается. Прозрачный фон поверх видео (настройка меню телетекста): чёрный фон — лёгкая вуаль, остальные цвета почти непрозрачные, знаки с тенью. Справа от страницы — экранная клавиатура, управление как в PIN «Google» — `docs/controls.md`. Только HLS: прямой TS по HTTP идёт через стандартные экстракторы и телетекста не покажет. Искать каналы с телетекстом — `tools/find_teletext.py`.
- **Формат кадра** (`Prefs.aspect`): вписать / растянуть / увеличить — `resizeMode` у `PlayerView`.
- **Таймер сна**: 15–120 мин, таймер интерфейса; по сроку — `finish()`.

**Деинтерлейсинг.** Настройка «Деинтерлейсинг» (раздел «Просмотр», `Prefs.deinterlace`, по умолчанию выключена): для чересстрочных потоков H.264 (`frame_mbs_only_flag = 0` в SPS) к видео подключается шейдер `DeinterlaceEffect` через `ExoPlayer.setVideoEffects` (`media3-effect`). Шейдер по одному кадру ищет «гребёнку» (пиксель выбивается из верхнего и нижнего соседей в одну сторону) и в таких местах смешивает соседние строки; статичная картинка не меняется, частота кадров не удваивается. Нагружает видеопроцессор; действует со следующего канала; применяется и аппаратному декодеру (кадр идёт через GL, а не прямо на экран). Включается и выключается только когда сменилось «чересстрочный / нет» у выбранной видеодорожки.

**Чтение программы не в главном потоке во время загрузки.** Замер на эмуляторе (полная перезагрузка 66 МБ XMLTV + быстрое листание гида): чтение программы канала в главном потоке занимало 90–240 мс против 5–40 мс без загрузки (запись загрузчика замедляет чтение в разы, а строки гида просят программу каждым кадром). Поэтому, пока идёт или стоит в очереди загрузка программы (`Repo.epgBusy()`), промах кэша в главном потоке не читает БД: возвращает пусто, ставит чтение в отдельный фоновый поток (`epg-read`) и после пачки прочитанных каналов шлёт `DataEvent.EpgRead` — гид и инфопанель перерисовываются. После загрузки — обычное синхронное чтение (кэш сбрасывается по завершении). Диагностика: в логе `slow epg read N мс` — чтение в главном потоке ≥ 30 мс. После правки на том же замере медленных чтений нет.

**LeakCanary (только debug-сборка).** `debugImplementation(leakcanary-android 2.14)` — утечки Activity, Fragment, View и ViewModel ищутся автоматически (уведомление при находке; в release библиотеки нет — проверено по APK). Настройки → Данные и резервная копия → **«LeakCanary»** (пункт есть только при `BuildConfig.DEBUG`) открывает его экран утечек (`leakcanary.internal.activity.LeakActivity`, запуск по имени класса — release без зависимости собирается). Сам LeakCanary добавляет в debug-сборку и свой значок «Leaks».

**Перехват ошибок и диагностика** (`core/Crash.kt`, `core/Diagnostics.kt`, `ui/CrashActivity.kt`, `ui/ReportActivity.kt`; по образцу DDDVideoPlayer). Фатальная ошибка: отчёт (устройство, исключение, 400 строк лога приложения) пишется в `files/crash_last.txt`, показывается экраном «Perfect TV закрылся с ошибкой» в отдельном процессе `:crash` (основной уже мёртв; там пропускается тяжёлая инициализация `App` и перехват, чтобы не было петли) — «Перезапустить», «Подробности», «Выйти». Настройки → Данные → **«Диагностика»** (пометка «есть ошибка», если файл есть) и «Подробности» открывают один экран: слева отчёт (↑/↓ — прокрутка), справа «Копировать» (в буфер), «Выгрузить (QR)» и «Закрыть». Отчёт: последняя ошибка, устройство (модель, Android, версия, ABI, куча, GL, язык), экран (режимы, HDR), аудиовыходы и проброс, видео- и аудиодекодеры (системные и встроенный FFmpeg, MP2), ключевые настройки просмотра, лог приложения (1000 строк `logcat`, свои записи). **Адреса сокращаются до хоста** (`Diagnostics.redact`: логин, пароль и путь провайдера не попадают ни в файл, ни в выгрузку). Выгрузка — только по кнопке: TCP на `termbin.com:9999`, ответ — ссылка, QR рисуется локально; ссылку видит любой, у кого она есть (об этом подсказка на экране). Тест — `DiagnosticsTest` (сокращение адресов).

**Ввод с телефона** (кнопка «С телефона» в форме плейлиста — название, адрес, свои источники программы — и в форме TMDB — ключ и адреса; `core/PhoneInput.kt`). Окно с QR-кодом (ZXing core 3.5.3, только кодирование) и адресом вида `http://<IP в локальной сети>:<порт>/<ключ 12 hex>`. Пока окно открыто, приложение слушает порт (`ServerSocket(0)`, один поток, без внешних библиотек): `GET` по ключевому пути отдаёт страницу с полями (подписи и текущие значения, `type=url` для адресов), `POST` присылает значения, они подставляются в поля формы (сохранять всё равно кнопкой «Сохранить»), окно закрывается. Любой другой путь — 404, тело запроса до 64 КБ, сервер закрывается с окном или через 10 минут. Передача по Wi-Fi открытым текстом (HTTP) — только в домашней сети; ключ в пути защищает от случайных обращений, но не от прослушивания сети. Нет сети (адрес не найден) — сообщение.

**Оформление субтитров** (Настройки → Просмотр, `player/SubtitleStyle.kt`, `Prefs.sub*`): размер (75–200 %), цвет текста (как в потоке / белый / жёлтый / зелёный / голубой), фон (как в потоке / нет / полупрозрачный / чёрный), обводка (нет / контур / тень), отступ снизу (4–18 %). Применяется к `SubtitleView` плеера при запуске и при возврате из настроек. «Как в потоке» (по умолчанию) не трогает цвета самих субтитров: у телетекста белый — речь, жёлтый — песня и т. п. Заданный цвет или фон заменяет цвета потока (для телетекста — при создании реплики, со следующей реплики).

**HTTPS с любыми сертификатами.** Плейлисты, программа, логотипы, TMDB и потоки идут через общий `Net.client`, в котором проверка сертификата и имени узла отключается настройкой «Принимать любые сертификаты» (Настройки → Просмотр, `Prefs.anyCert`, **по умолчанию включена**; читается на каждом соединении, перезапуск не нужен): у провайдеров часто просроченные и самоподписанные сертификаты. При включённой защиты от подмены соединения нет; выключена — системная проверка.

**Звук: программные декодеры FFmpeg.** `app/libs/lib-decoder-ffmpeg-release.aar` — расширение Media3 1.9.0 (`FfmpegAudioRenderer`), собранное в проекте DDDVideoPlayer (FFmpeg 6.0, декодеры vorbis, opus, flac, alac, pcm_mulaw, pcm_alaw, mp3, amrnb, amrwb, aac, ac3, eac3, dca, mlp, truehd; ABI arm64-v8a, armeabi-v7a, x86, x86_64). Включён режим `EXTENSION_RENDERER_MODE_ON`: сначала декодеры системы, FFmpeg — если системного нет (на эмуляторе и части приставок нет MP2 и AC-3, а вещательные потоки, например «Первый», идут с MP2). Проверено на эмуляторе: MP2 (`audio/mpeg-L2`) декодируется (`audio decoder ffmpegLavc60…` в логе, тег `IPTV`). Лицензия FFmpeg — LGPL 2.1+ (динамическая библиотека в AAR); DDDVideoPlayer — GPLv3. Версия AAR должна совпадать с `media3` в `gradle/libs.versions.toml`; пересборка — по `app/libs/README.md` того проекта.

**Зависание видео.** Флаги разбора TS (`Playback.tsFlags`) общие для HLS и прямого TS по HTTP (`DefaultExtractorsFactory`, поиск меток времени на 5000 пакетов): `ALLOW_NON_IDR_KEYFRAMES`, `DETECT_ACCESS_UNITS` (границы кадров по access unit, а не по началу PES), `ENABLE_HDMV_DTS_AUDIO_STREAMS`, `IGNORE_SPLICE_INFO_STREAM`; сбой загрузки — не меньше 5 повторов. HLS (MPEG-TS) играется через `HlsMediaSource` с `FLAG_ALLOW_NON_IDR_KEYFRAMES`: потоки, где ключевые кадры — non-IDR I с recovery point (вещательные кодеры), иначе не стартуют (буферизация без конца или первый кадр). Настройка «Видеодекодер» (раздел «Просмотр», `Prefs.videoDecoder`): «Авто» (по умолчанию) — аппаратный, со сторожем; «Аппаратный» — без сторожа; «Программный» — всегда программный (действует со следующего канала). Сторож зависания в режиме «Авто» (`Playback.checkStall`, раз в секунду): плеер играет, а счётчик показанных кадров не растёт 8 с — включается программный видеодекодер (звук не трогаем); поправка запоминается за каналом (`Prefs.playFix`), сбрасывается в меню канала («Сбросить поправку потока»). Диагностика — тег `IPTV`: декодеры, дорожки (кодек, размер, чересстрочность по SPS), первый кадр, потеря кадров.

## 9. Интерфейс

Один экран (`TvActivity`) с видео и слоями-оверлеями (стек слоёв в `Tv`): верхний слой получает клавиши, без слоёв клавиши получает плеер. Палитра, размеры, фокус, логотипы — `docs/design.md`. Шрифт — системный sans-serif.

Повторяемые элементы:

**Стартовый экран.** Без плейлистов открывается мастер: «Добавить плейлист» (URL, имя) — экранная клавиатура системы. С плейлистами — сразу плеер на последнем канале. Если последнего канала нет — гид на первой категории.

**Поиск.** По названиям каналов (и номеру) и по названиям передач: идущие, будущие на неделю, прошедшие в пределах архива канала. Программа читается по каналам плейлиста через индекс `(source_id, xml_id, start)` в фоновом потоке, сравнение без учёта регистра — в коде; не больше 400 находок, по 30 в разделе. Недавние запросы — `Prefs.searchRecent`. Экран и клавиши — `docs/controls.md`, «Поиск».

**Виды гида** (`Prefs.guideMode`: 0 «ТВ-гид», 1 «Каналы + программа», 2 «Категории + каналы», 3 «Каналы»; прежняя настройка guide_grid читается, пока новая не выбрана): 2 и 3 — правая часть экрана не затемнена, программа выезжает из-под списка по →. **Вид «Каналы + программа»** (`GuideLayer`): три колонки — каналы, передачи канала в фокусе (`Repo.range` от начала архива до недели вперёд, как в окне «Программа»), компактные даты. Настройки «Шапка гида» (`Prefs.guideHeader`: 0 канал + передача, 1 канал, 2 скрыть; действует и в таблице) и «Описание в ТВ-гиде» (`Prefs.guideDesc`: панель передачи со сдвигом каналов к колонке логотипов). Клавиши — `docs/controls.md`, «ТВ-гид, вид «Список»».

## 10. Управление (пульт)

**Тач и мышь**: по видео тап — инфопанель (на сенсорных устройствах, не ТВ, — с кнопками ◀ ❚❚ ▶, «О передаче», «Гид», «Меню», «Недавние»), двойной тап или свайп вверх — гид, свайп вниз — недавние каналы, свайп влево/вправо — канал (в архиве — перемотка). В гиде: тап по каналу — смотреть, по передаче — карточка, долгий тап или правый клик — меню, вертикальное перетаскивание или колесо — каналы, горизонтальное или Shift+колесо — время, тап по названию категории — колонка категорий, ✕ — закрыть (на сенсорных). В окнах: тап — выбрать, тап вне окна — закрыть, список программы прокручивается пальцем и колесом.

Клавиши пульта идут прямо в обработчик экрана (`TvActivity.dispatchKeyEvent`), мимо View: иначе стрелки уводят фокус Android на кликабельные элементы окон, и OK «кликает» по ним.

Раскладка — `docs/controls.md`. Ниже — то, что важно для реализации:

- Коды клавиш: DPAD_*, DPAD_CENTER/ENTER/NUMPAD_ENTER (OK), BACK/ESCAPE, CHANNEL_UP/DOWN и PAGE_UP/DOWN (PG±), 0–9 и NUMPAD_0–9, MEDIA_PLAY_PAUSE/PLAY/PAUSE/STOP/REWIND/FAST_FORWARD, GUIDE (гид), INFO (инфопанель), MENU (меню канала), PROG_RED/GREEN/YELLOW/BLUE — зарезервированы.
- **Долгие нажатия** (`ui/Keys.kt`): если у слоя есть долгое действие для клавиши, короткое срабатывает на keyup, а долгое — через 500 мс удержания; после долгого автоповтор этой клавиши игнорируется до keyup. Удерж. OK — 800 мс, MENU — сразу меню.
- **Удержание ↑/↓ в списках** листает своим таймером, а не автоповтором системы: старт через 350 мс, интервал от 90 до 35 мс за 1,5 с, интервал считается без времени шага (`HOLD`).
- **Назад ×2** выходит из приложения (тост «нажмите ещё раз»); на закрытом канале — возврат к последнему незаблокированному. Первое «назад» отменяет набор номера и перемотку, сворачивает описание, закрывает закреплённую инфопанель.

## 11. Настройки (минимум)

Два столбца: слева — разделы («Плейлисты», «Просмотр», «Внешний вид», «Список каналов», «Блокировка», «TMDB», «Данные и резервная копия»), справа — пункты раздела (название, подпись, значение справа «‹ … ›»). После изменения пункта фокус и прокрутка остаются на месте.

- Клавиши. В разделах: ↑/↓ — раздел (страница справа меняется сразу), → / OK — к пунктам, «Назад» — выйти. В пунктах: ↑/↓ — пункт, ← / → — предыдущее / следующее значение по кругу (у пункта без значений ← — к разделам), OK — следующее значение или действие, «Назад» — к разделам. Формы (плейлист, PIN, TMDB, скрытое) открываются справа, разделы на это время недоступны. Внизу — подсказки клавиш.
- **«Размер интерфейса»**: меньше / нормальный (по умолчанию) / больше (`Prefs.uiScale`, ключ `ui_scale`). Плотность подбирается под высоту экрана 540, 480 или 432 dp (`Prefs.screenDp` в `Lang.wrap` и `U.init`), шаг — 12,5%; экраны пересоздаются. Окна шире экрана сужаются сами, меню канала в крупных размерах прокручивается.
- **«Вид гида»**: ТВ-гид / список (то же, что «Вид» в меню канала).
- **Приоритет логотипов** (раздел «Внешний вид», `Prefs.logoPriority`): «Плейлист» (по умолчанию) или «Программа» — из какого источника логотип берётся первым (`tvg-logo` плейлиста или иконка канала из XMLTV). Не загрузился (ответ сервера, битая картинка, нет связи) — берётся другой источник, а адрес запоминается как неудачный: ошибка сервера и битая картинка — на 12 часов и между запусками, нет связи — на 3 минуты; пока срок не вышел, адрес не запрашивается. Нет ни одного — монограмма. Очистка «Кэша логотипов и баннеров» сбрасывает и список неудач.
- **Резервная копия** (`data/Backup`): один JSON с датой создания (`created`) — настройки, плейлисты (без каналов), избранное, недавние, скрытое, блокировки, очки сортировки, напоминания. Имя файла — `backup-YYYYMMDDHHMMSS.perfecttv` (местное время; прежний `perfecttv-backup.json` тоже восстанавливается). «Сохранить» — системным выбором места, а если его нет (на Android TV и Google TV часто заглушка или нет совсем) — в **«Загрузки/PerfectTV»** (Android 10+ через MediaStore без разрешений, тип `application/octet-stream`, чтобы имя не получило `.json`; Android 9 и ниже — файлом с правом `WRITE_EXTERNAL_STORAGE`); не вышло — в папку приложения `Android/data/top.rootu.perfecttv/files/`. «Восстановить из копии» открывает **список копий** (новые сверху: имя, дата, размер; источники — «Загрузки/PerfectTV», корень «Загрузок», папка приложения) — пользователь выбирает, какую восстановить, и подтверждает; внизу «Выбрать файл…» (если есть системный выбор). Чужие файлы, положенные в папку файловым менеджером, на Android 10+ приложению не видны: их открывают из менеджера (`*.perfecttv`) или системным выбором. **Открытие файла `*.perfecttv`** (`RestoreActivity`, фильтр `VIEW` для `content://` и `file://`, с типом и без, шаблоны пути на расширение + тип `application/x-perfecttv`): любой файловый менеджер или мессенджер предлагает открыть его в Perfect TV. Любое восстановление идёт через **подтверждение** (`RestoreDialog`): «Восстановить копию от <дата из файла>? …», кнопки «Отмена» (в фокусе) и «Восстановить»; не копия Perfect TV — сообщение. Восстановление заменяет перечисленное, плейлисты скачиваются заново, приложение перезапускается.

- **Плейлисты**: добавить, изменить имя и URL, удалить, обновить, порядок. У каждого — **«Программа (EPG)»**: показаны URL из плейлиста (только чтение, со статусом загрузки) и свои URL (добавить, изменить, удалить), а также режим: «Из плейлиста» / «Из плейлиста + свои» / «Только свои». У сохранённого плейлиста режим (вместе со своими URL из поля) сохраняется сразу при переключении, без кнопки «Сохранить»; имя и адрес — по «Сохранить».
- «Номер канала»: не показывать / рядом с названием («2. Россия 1», колонка номеров в гиде) / бейдж на логотипе (по умолчанию). Без логотипа — монограмма названия на цветной плашке.
- Глубина архива по умолчанию (1–14 дн), «Клавиша ↑ в плеере» (архив / недавние), «Напоминать о передаче» (когда начнётся, за 1/2/3/4/5/10 мин), «Скрывать инфопанель через» (3/5/7/10 с), «Подсказки клавиш», «Плавные анимации», «Адаптивная сортировка» и сброс очков, «Скрытые категории и каналы», «Запускать последний канал», «Обновлять программу каждые» (6/12/24 ч).
- **Блокировка**: PIN из 4–6 цифр (задать, сменить, убрать), «Спрашивать PIN: каждый раз / один раз до выхода», «Ввод PIN»: кольцо (как Fire TV: ↑→↓← = 1–4, OK = 0, «Меню» или удерж. OK — раскладка 5–9), ряды (как Google: ←/OK/→ — цифры ряда, ↑/↓ — ряд, с 1-2-3 вверх — 7-8-9, на 7-8-9 ↓ = 0) или клавиатура. В кольце и рядах нажатая цифра не подсвечивается; видны только набранные точки по центру — длина PIN не видна. «Назад» стирает цифру, на пустом — закрывает. Проверка принимает PIN, как только он набран; 6 цифр без совпадения — «Неверный PIN». Новый PIN — клавиатурой с «Готово» (ввод дважды). Каналы и категории блокируются в меню канала (при первой блокировке PIN задаётся там же), заблокированные отмечены замком в гиде. Цифры пульта работают в любом способе ввода — но у многих пультов Android TV цифр нет. Без PIN отметки блокировки не действуют.
- **Описания (TMDB)**: ключ API v3 или токен v4, адреса API и картинок (можно прокси), кнопка «Проверить». С ключом ↓↓ в плеере показывает баннер, год, рейтинг и описание TMDB (подбор: очищенное название, год из EPG, сходство Левенштейна, без года — только однозначный и точный результат).
- **Файл плейлиста**: системный выбор файла; если его нет (на Android TV часто заглушка) — встроенный список .m3u/.m3u8 в памяти, «Загрузках» и на USB (`/storage/*`).
- **Очки адаптивной сортировки копятся всегда** (канал, на котором смотрели дольше порога), даже если сортировка выключена: после включения порядок сразу готов, а ряд «Популярные» на главном экране берёт те же очки. Выключенная сортировка только не применяет их к порядку каналов.
- Порядок плейлистов («Выше» / «Ниже»), «Скрытые категории и каналы» всех плейлистов, сброс очков адаптивной сортировки, «Запускать последний канал» (выкл. — при запуске гид).
- Ввод с пульта — системная клавиатура. Позже, по желанию, — ввод с телефона по QR-коду: локальный HTTP-сервер приложения (фаза 5).

**Главный экран Android TV** (`data/Home.kt`, настройка «Главный экран Android TV», по умолчанию включена; право `WRITE_EPG_DATA`). При уходе приложения с экрана (`TvActivity.onStop`) в фоновом потоке обновляются: ряд «Популярные» — канал-превью по умолчанию (виден сразу) с самыми смотримыми каналами (до 12, по очкам адаптивной сортировки; логотип, название, текущая передача), «Избранные» — второй канал-превью с карточкой на каждый избранный канал (до 12; пользователь включает его в «Настроить каналы» главного экрана) и «Продолжить просмотр» — карточка последнего канала. Скрытые и заблокированные каналы на главный экран не выносятся. Баннеры карточек рисуются самими (`data/Posters.kt`, 800 × 450, JPEG в `cacheDir/posters`, лаунчеру отдаёт `Posters.Provider`): логотипы бывают квадратными, круглыми и вытянутыми. С картинкой передачи (TMDB, если включён и ответил за 4 с, иначе EPG) — картинка на весь баннер, снизу затемнение, логотип канала в прямоугольнике (как логотипы в программе, 1,45 : 1, тёмная плашка с тонкой каймой) в левом нижнем углу; без картинки — логотип на сером фоне, как баннер «О передаче» в плеере; у канала нет логотипа (или он не загрузился) — на картинке передачи значок приложения (`icon.xml`) вместо логотипа, в той же рамке (файл «i»), а без картинки — баннер приложения. Баннеры входят в «Кэш логотипов и баннеров» (размер и очистка — в настройках, раздел «Данные»); при выключении настройки главного экрана удаляются; не публиковавшиеся дольше суток удаляются, а при превышении 10 МБ — самые старые, при старте процесса (в том числе когда лаунчер сам поднял провайдер) и при каждом обновлении — карточки обновляются при каждом уходе из приложения, дольше файлы лаунчеру не нужны. Имя файла — канал + начало передачи + «a» (с картинкой) или «n» (без): готовое не рисуется заново. После трёх подряд не загрузившихся картинок остальные в этом обновлении не пробуются. Карточка запускает глубокую ссылку `perfecttv://channel?p=<плейлист>&k=<ключ>`; приложение сменяет плейлист, если нужно, и включает канал. Голос: `android.media.action.MEDIA_PLAY_FROM_SEARCH` — номер или название канала включаются сразу, иначе открывается поиск с этим запросом. Идентификаторы карточек в резервную копию не входят. На устройствах без провайдера ТВ ошибки глотаются.

## 12. Нефункциональные требования

- Холодный старт до видео с последним каналом — меньше 2 с на S905X3 (кроме сети). Каналы берутся из БД, плейлист в фоне не перекачивается, если не устарел (по умолчанию — 24 ч).
- Переключение канала ←/→: инфопанель — сразу, видео — через 0,7 с.
- Гид листается без рывков: 60 fps на Chromecast with Google TV, не ниже 30 на S905X. Сетка рисуется одним View без выделения памяти на кадр.
- Плейлист на 10 000 каналов, EPG на 1000+ МБ — без OOM при `largeHeap=false`.
- Сеть: таймаут подключения 10 с, чтения 30 с. HTTP-кэш OkHttp — 20 МБ.
- Язык интерфейса — русский и английский: настройка «Язык» (по умолчанию системный: ru/uk/be/kk — русский, иначе английский). Строки — ресурсы Android: `res/values/strings.xml` (английский, по умолчанию) и `res/values-ru/strings.xml`, счётные — `plurals`; язык применяется локалью контекста, на Android 13+ — и как системный язык приложения. Тест `LangTest` сверяет оба файла (ключи и подстановки). Обычные экраны (окна, инфопанель, PIN, настройки, формы) — XML-разметка в `res/layout`; гид и списки программы рисуются на Canvas.
- Логи — `Log` с тегом `IPTV`, в release без подробностей.

## 13. Проверка

- Юнит-тесты (JVM): M3U, XMLTV (на Robolectric или kxml2 в тестах), матчер EPG, шаблоны архива, ячейки сетки и окна времени, разбор клавиш (долгие нажатия, удержание).
- Ручная проверка на эмуляторе Android TV (API 30, 720p) и на реальной приставке: чек-лист сценариев (`docs/checklist.md`); архив Flussonic — `tools/flussonic_mock.py`.
